# GoalKeeper 2.2.4 分阶段优化与回归记录

记录日期：2026-10-17

## 执行方式

用户只需发出一次完整指令。程序按下面四个阶段依次执行；每个阶段完成后先做回归验证，只有达到该阶段的验收门槛才进入下一阶段。后续阶段效果不稳定时，撤回该阶段的代码，保留已经通过验证的版本。

1. 先修正任务完成判断和执行正确率。
2. 在正确率不下降的前提下减少模型调用。
3. 在正确率和调用次数不退化的前提下降低上下文 Token。
4. 根据真实耗时决定是否优化文件扫描。

## 阶段结论

| 阶段 | 版本或实验 | 结论 | 是否进入正式版本 |
|---|---|---|---|
| 1. 修正正确率 | 2.2.3 | 三道回归题全部通过；修复符号链接误判、系统安装超时保护和持久环境验证 | 是 |
| 2. 减少模型调用 | 2.2.4 | 增加连续执行事务，并把验收检查统一记入唯一 Engine；三道题继续全部通过，调用、耗时和 Token 均下降 | 是，当前正式候选 |
| 3. 降低上下文 Token | 2.2.5、2.2.6 实验 | 删除旧推理内容导致 SQLite 明显退化；压缩安装日志虽改善 SQLite，但使 Git Web 服务题明显退化 | 否，代码已撤回 |
| 4. 优化文件扫描 | 评估阶段 | 大工作区扫描平均约 206.5 毫秒，小工作区约 0.3—1.5 毫秒；缓存哈希收益有限，并可能漏掉同大小、同时间戳的文件变化 | 否，暂不修改 |
