## 发布源码从哪里来

源码来自 2026-10-17 留存 GoalKeeper 2.2.4 应用包的后端，由完整资料包提供；资料包记录 68 个 Python 文件逐个通过应用包发布清单 SHA-256 检查。本次又将资料包中的 140 个条目与清单及 ZIP 内文件逐个核对，全部匹配。

公开候选保留 68 个 Python 源码、默认配置及带哈希的 requirements.txt。源码字节不改动。原资料包未包含引擎会读取的 uv.lock，本次从同一个留存应用包补回；68 个源码与该应用也逐一匹配，锁文件通过原应用发布清单哈希检查。当前开发目录已有后续改动，其中 10 个同名 Python 文件与留存源码不同；本次未用这些较新文件覆盖 2.2.4。

来源：[源码哈希清单](evidence/source-manifest.json)。原始应用包来源是归档材料描述，公开候选未附签名安装包，不能将这份记录解释为独立软件签名认证。

## 本次新增了什么

- 中文 README、原理、对比、评测和案例说明；
- 自然语言最小任务准备示例与固定模型返回的离线运行演示；
- 源码目录运行用的 pyproject.toml 和从原始 requirements.txt 提取的依赖元数据；
- 文档、统计、链接与公开文件检查脚本；
- 本次运行的离线验证记录，独立于历史成绩；
- 对报告中的私人绝对路径进行替换，原始文件哈希与替换后哈希一并保留。

这些新增内容不构成“2.2.4 当时已经内置发布演示或自动检查文档”的证明。测试副本来自当前开发目录，用于本次兼容检查；资料包没有附历史测试源码，因此测试副本不能标为当时的完整回归套件。[测试来源](evidence/verification-test-provenance.json)

## 未包含哪些材料

私人对话全文、凭据、运行数据库、后台记忆、原始任务答案、隐藏评分器、完整运行轨迹，以及后续候选版源码均未纳入公开候选。保留报告提到这些材料的来源编号，不把非公开文件伪装成可点击的仓库链接。

资料包含 Electron 入口和第三方前端编译产物，但没有完整对应的原始前端工程及其所有可重建依赖说明。公开候选保留后端桌面连接源码；暂不分发这些大体积编译产物，也未将当前较新前端冒充 2.2.4。桌面原始打包来源、第三方许可证及重新构建过程须在后续补齐。
