# 历史 16 题评测：交付、质量与效率分开看

[返回首页](../../README.md)

## 先说明版本与能证明的范围

这是 2026-10-07 汇总的历史自建/改编任务评测，公开发布记录为 cf43b9b，各批实际运行使用不同实现快照。主体为当时的命令行执行，不能写成“2.2.4 桌面版重新跑完 16 题”。cf43b9b 是公开发布记录，不代表每次运行的精确源码哈希。

四组使用 gpt-6.1-sol / xhigh，每组每题最多 1800 秒。C1-v2 当时另有每组 100 万 Token 限额，后续批次关闭累计额度；因此完整历史范围并非所有时间与累计用量限制完全一致。

对照产品为 Codex、OpenCode、Pi；Claude Code 不在同模型实测组中。源码机制对比采用的固定版本另见[对比文档](../comparison.md)，不能将后来代码核查等同于各批运行字节证明。

## 怎样运行与计分

- 每题每组选择一轮，共 16 题、4 组、64 次交付；CONNECT、准备、离线检查和其他重跑不计入这张成本表。
- 四组运行各自的执行循环。比较目标是同模型条件下框架及其默认工作方式的整体表现，不能声称只改了一个独立变量就验证某个单项设计。
- 失败保留在所报告样本分母内；不同历史阶段的重跑不覆盖旧记录。运行结束后另行核对质量与兼容性。
- Token 为输入加输出，包含摘要；缓存输入与推理输出作为子集不重复累加。未知用量不补零，总体 Token 只能写已知下限。
- 累计耗时为每题时间相加，包含模型等待，非四组并行时的实际等待时间，也不能直接换算账户现金支出。

由于四组总量都有未知用量，不能直接用总量下限宣称“全 16 题成本确定减少 57%”。

## 题目可信度与限制

验收由运行后的独立质量检查和人工复核补充。冻结交付快照用于避免后续修改污染当时交付；执行 Agent 不应修改受保护检查和隐藏评分。但外部素材原始隐藏评分器未提供，项目使用披露的本地检查与人工复核，不能声称所有题都经过同一套官方隐藏验收。

SB10-06/07 的可见资料带有预期动作提示；SB10-10 的 SYSTEM.md 是普通文件。SB10-03 的 Pi 双格式方案存在默认模式解释差异。报告保留这些限制，未将五道低复杂度任务统称高难长任务。
