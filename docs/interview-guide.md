# 面试现场建议浏览顺序

[返回首页](../README.md)

1. **从首页开头说问题**：长任务为什么会遗漏要求、提前交付或反复消耗输入。说明模型和框架各管什么。
2. **打开主流程图**：用四步讲任务怎样运行，交付核对放在模型申请之后。提问时再点源码。
3. **展示离线演示**：说明模型返回预设，展示真实引擎如何拒绝缺文件的申请。将流程演示与模型能力评测分开。
4. **打开设计取舍与对比**：选择一个差异讲透，例如 Pi 的树状会话与本项目的连续任务状态，或交付核对与停止处理的差别。
5. **打开两套评测**：先交代题集、版本和模型，再讲通过率、耗时、Token。历史 16/16 使用“正常交付”的准确含义。
6. **主动展示一个失败**：DNA 引物任务说明专业验收的重要性；MIPS 任务说明本版存在能力短板。
7. **最后说明个人贡献**：解释为什么收缩范围、如何要求公平比较、如何审查结果，以及 AI 参与了哪些实现。

推荐追问入口：[主循环](../src/goalkeeper/engine.py#L587)、[交付核对](../src/goalkeeper/runtime/completion.py#L228)、[历史逐题检查](evidence/reports/historical-16/benchmark-results.json)、[已知边界](architecture.md#交付核对具体能保证什么)。

如果被问“是不是所有任务都比 Codex 更好”，按批次展示成绩与失败，不把部分样本结论扩大。若被问“用户要写测试才能用吗”，先解释自然语言模式，再解释评测中的预设检查来自评测或部署任务的人。
